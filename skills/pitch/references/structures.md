# Choosing a structure

These are editorial options derived from the source review. Adapt sequence, duration and slide count to the context; mandatory jury formats take priority. See [source notes](source-notes.md) for research limits.

| Situation | Narrative spine | Example | Watch for |
|---|---|---|---|
| Strong real usage | Definition → usage/commercial evidence → mechanism behind the advantage → economics → meeting | GitLab | Users are not necessarily paying customers. |
| Unfamiliar category, understandable savings | Definition → everyday example → same task before/after → mechanism → current evidence → ask | Retool | One case doesn't guarantee the same result across a market. |
| An expected "already solved" objection | Definition → unsolved context → gaps in alternatives → operation → result → broader goal | DoorDash | Use current evidence for competitor comparisons. |
| Value becomes visible through action | Need → what will be shown → action → result → meaning → related second proof → trial | Dropbox, Scrub Daddy | Avoid a demo catalog; prepare a fallback. |
| One major obstacle blocks the decision | Benefit → concrete action → obstacle addressed → observable evidence → decision | Getaround, Cloudflare | Establish the scope of security or insurance claims. |
| Customer is satisfied with their current setup | Current setup → small frictions → new setup → everyday difference | Slack | A commercial film scene isn't an independent customer statement. |
| Early technical product, limited commercial evidence | User job → working component → its result → uncertainty → next validation | Correction drawn from Figma | Multiple prototypes don't establish a mature product. |
| Anticipated launch by an established brand | Reason → previous stages → new product benefit → specific obstacles → trial | Model 3; iPhone segment | Don't transplant a long buildup into a short early-stage pitch. |

## Example budget for 3 minutes

A starting plan, not an ideal duration established by the recordings.

| Section | Planned time | Purpose |
|---|---:|---|
| Product / user job | 0:00–0:20 | What we do |
| Current difficulty and its consequence | 0:20–0:45 | Why it matters |
| Demo / mechanism / before-after | 0:45–1:35 | How the benefit arises |
| Evidence and main objection | 1:35–2:10 | Assessing the claim |
| Economics / jury-specific reasoning | 2:10–2:40 | Decision context |
| Main idea and one next step | 2:40–2:55 | Close |
| Buffer | 2:55–3:00 | Small delays |

Rework this around the speaker's pace, criteria and demo. It doesn't impose a slide count. If rehearsal runs long, cut repetitions, side examples and unnecessary detail rather than relying on faster speech.

## Q&A distinctions

- "How?" calls for the mechanism; "why does it matter?" calls for the customer result.
- "Is it used?" calls for usage evidence; a waiting list isn't usage.
- "Will they pay?" calls for purchase or pilot evidence and remaining unknowns; interest isn't revenue.
- "How is it different?" calls for a mechanism or comparison on the same job, not broad superiority claims.
- "Can I trust it?" calls for validation scope and remaining risk; don't invent guarantees.
- "Why now?" calls for a documented change relevant to this product; don't borrow an example company's history.
